# 数据与批量任务规则

## 1. SQLite 是本地真相源

章节、索引、状态和分析结果全部明文存储在 `${DATA_DIR:-data}/novel-chapters.sqlite`，`DATA_DIR` 由 `server/config.js` 解析，新脚本不得假定数据库永远位于固定绝对路径

删除影响：可能读写错误数据库，导致索引结果与当前运行环境不一致

## 2. 备份必须包含 WAL 伴生文件

数据库使用 WAL 模式，备份或迁移时必须在停止写入后一并处理 `novel-chapters.sqlite`、`novel-chapters.sqlite-wal` 和 `novel-chapters.sqlite-shm`

删除影响：可能丢失尚未 checkpoint 的新数据，产生看似成功但内容不完整的备份

## 3. L2 数据必须按书籍和索引组隔离

L2 事实从 `l2_facts` 读取，查询必须同时限定 `book_id` 和 `index_group_key`，并结合 `l2_chapter_statuses` 判断覆盖与新鲜度，索引组配置以 `book_index_groups` 为准

删除影响：会混入其他书籍或其他 L2 主题的事实，并可能使用过期索引

## 4. 不通过删库解决普通故障

删库、覆盖、迁移或批量更新前必须明确作用范围并完成可恢复备份

删除影响：普通排障可能升级为原文、索引和历史任务的不可逆丢失

## 5. 批量任务必须先固化作用范围

导入、索引、分析、生图和上传前，必须记录书籍、索引组、章节范围、筛选条件、任务数和输出目录

删除影响：可能把子集误当全量，或向错误对象批量写入

## 6. 索引新鲜度以执行证据为准

L1/L2 新鲜度以章节 `content_hash`、Prompt 哈希和工作流执行签名为准，章节或工作流版本变化后必须重新判断是否需要构建

删除影响：可能将过期事实当作最新证据，或无意义地重复消耗 LLM 调用

## 7. 长任务必须可追踪和可恢复

批处理必须保存稳定任务 ID、进度、成功项、失败项和断点，已成功且产物有效的项目不得默认重跑

删除影响：中断后无法确认真实进度，并会增加重复成本和重复写入风险

## 8. 完成状态必须有结果证据

任务启动、部分进度或局部文件不等于完成，只有在文件落盘、数量校验、目标系统写入和读回验证完成后才能宣告交付完成

删除影响：会把进度误报为结果，造成文件、记录或远端写入缺失

## 9. 密钥不得进入代码和产物

API Key 和 Dify Key 只通过本地环境变量传入，不得出现在源码、Prompt、JSONL、日志、截图、评审文件或最终报告中

删除影响：可能泄露外部服务凭据并产生额外费用或数据风险
