## 2. 目标与范围

角色库用于把分散在章节中的角色事实聚合为稳定、可浏览、可追溯的角色与阶段档案

第一阶段采用展示优先策略，提供角色表格、角色详情抽屉、阶段切换、核心档案和外形事实证据，不提供人工归并工作台

本期包含：

- 书籍首页新增独立角色库入口
- 支持按部分章节建立和增量更新角色库
- 只收录有稳定名称的角色
- 从 L2 角色事实聚合角色和阶段
- 展示姓名、确认别名、性别、阶段、年龄、身份或职业、稳定外形、稳定气质、原文五官、设计五官
- 展示与角色外形形象有关的事实及章节证据
- 展示构建覆盖、数据新鲜度和质量警告

本期不包含：

- 角色图片生成、重绘、上传和图片入口
- 完整角色关系图谱
- 人工合并、拆分和别名裁决工作台
- 将现有角色形象索引从事实索引迁出
- 跨书角色库
- 任意字段模板设计器

## 3. 术语与依赖链

L1 是章节线索和角色路标，不是事实索引；角色事实来自 L2 角色专项索引

角色库的正确依赖链为：

`章节原文 → L1 角色路标 → L2 角色事实 → 角色归并与阶段拆分 → 角色核心档案`

现有 `characters` 或其他实际承载角色事实的 L2 索引组继续由事实索引功能管理，角色库只读取其已完成且新鲜的事实，不修改 L2 原始事实

## 4. 角色入库规则

正式角色列表只收录有稳定名称的主体，包括：

- 原文明示的本名
- 原文明示的化名或改名
- 能稳定唯一指向一个主体的专属称号或稳定绰号

以下对象不得进入正式角色列表：

- 组织、势力、物品、地点、境界和能力名称
- 无法唯一指向具体主体的泛称
- 临时描述性称谓，如黑衣人、侍卫、路人和某人的母亲
- 只有模型推断、没有原文命名依据的主体

同名、疑似别名或疑似同人但缺少强证据时保持为独立候选，不自动合并

## 5. 核心档案

角色层保存：

- 稳定角色 ID
- 书籍 ID
- 规范姓名
- 确认别名
- 性别
- 首次和最近出现章节
- 关联阶段数
- 关联外形事实数
- 档案状态和更新时间

阶段层保存：

- 稳定阶段 ID
- 所属角色 ID
- 阶段名称
- 阶段类型，如年龄时期或形态
- 起止章节或适用章节范围
- 年龄
- 身份或职业
- 稳定外形
- 稳定气质
- 原文五官
- 设计五官
- 来源事实与证据引用
- 构建状态、质量状态和更新时间

所有字段都允许未知，不为了填满档案而猜测

## 6. 阶段识别

阶段采用保守自动拆分，默认每个角色只有一个默认阶段

只有以下条件同时成立时才创建独立阶段：

- 原文存在明确的年龄时期、时间节点、身份形态或物种形态变化
- 不同阶段存在稳定外形、体型、年龄感、气质或形态差异
- 每个阶段都有独立可追溯的事实和原文证据

可接受的阶段示例包括幼年、少年、成年、老年、人类形态、非人形态、鬼魂形态和投胎后形态

临时伤病、哭泣、战损、换装、易容、一次性戴面罩或面纱、短暂力量异变和单场景情绪不得作为阶段拆分依据

长期稳定佩戴的面罩、面纱或其他遮挡物可以进入对应阶段的稳定外形，但必须有跨章节或明确长期设定证据

## 7. 事实层与设计层

角色档案必须明确分开原文事实和设计推导

原文事实层包括：

- 原文明示的姓名、别名、性别、年龄、身份和职业
- 原文明示的稳定体型、肤色、发型、服饰惯例、标志物和其他稳定外形
- 原文明示或由多处稳定行为支持的气质
- 原文明示的脸型、眉形、眼型、鼻形、唇形、下颌、骨相和其他五官特征

设计层只用于补足角色形象设计所需但原文缺失的五官组合：

- 结合年龄、性别、稳定外形和稳定气质生成差异化五官设计
- 不得改变或覆盖原文明示特征
- 不得把题材套路、模型偏好或审美模板写成角色事实
- 必须显示“设计推导”标记
- 必须显示“基于年龄、稳定外形与气质生成，不等同于原文事实”说明
- 必须记录使用的事实依据和生成版本

## 8. 稳定外形与稳定气质

稳定外形只保留跨场景成立或被原文明示为长期设定的特征

受伤、哭泣、醉酒、脸红、疲惫、病后憔悴、单次服装、临时战损和短暂遮挡不进入稳定外形

稳定气质用于辅助后续角色形象生成，应来自角色长期个性表达、稳定行为方式、叙述性评价或多处相互支持的原文证据

单次情绪、单一角色的偏见、传闻、表演性人格和伪造文本不得直接成为稳定气质；存在表里人格时必须保留语境层级

## 9. 角色事实质量要求

### 9.1 结构准确度

- 角色事实的 `category` 必须为 `character`
- `fact_type` 只允许 `identity`、`alias`、`appearance`、`age`、`personality`、`background`
- entity、fact 和 evidence 不得为空
- importance 和 confidence 必须在 0 至 1 范围
- 同章完全重复事实必须在聚合前去重

### 9.2 主体准确度

- entity 必须是稳定主称或明确标记的候选主体
- 昵称、头衔和关系称谓不得无条件成为独立角色
- 自动别名合并只允许原文明示改名、化名揭示或姓名与唯一专属称号互证等强证据
- 同章出现、共享关系人、模糊字符串相似和模型自行列出的 aliases 不足以自动合并

### 9.3 事实准确度

- 每条进入档案的事实至少有一条直接证据和章节定位
- 推断内容必须标明推断性质，不能混入原文事实
- 稳定外形不得混入临时状态
- 公开身份、真实身份、回忆、传闻、角色误判和伪造文本必须保留来源语境
- 冲突事实不得静默覆盖，应在质量状态中暴露

### 9.4 完整度

- 使用 L1 角色路标作为候选召回和异常空章对照，不把 L1 当作档案事实来源
- L1 有明确角色信号但 L2 无角色事实的章节标记为疑似异常空章
- 明确区分原文无信息、未覆盖章节和疑似漏抽
- 构建结果必须显示 L1、L2 和角色库各自的章节覆盖范围
- 章节哈希、Prompt、Schema 或工作流版本变化后，受影响角色库标记为需更新

### 9.5 验收目标

- 机器结构校验通过率 100%
- 抽样角色事实准确率不低于 95%
- 抽样有稳定名称角色召回率不低于 95%
- 高价值身份和别名误合并为 0
- 阶段拆分必须全部具备独立证据
- 设计五官与原文事实混写为 0

### 9.6 结构化投影输入契约

角色库投影层只消费已经完成语义判断的结构化字段，不负责从自然语言事实正文推导别名关系、阶段稳定性或持续时间

角色别名字段：

- `alias_relation`：只允许 `confirmed`、`candidate`、`rejected`
- `alias_confidence`：0 至 1 的数值
- `evidence`：至少一条非空原文证据
- 自动归并只接受 `alias_relation=confirmed` 且 `alias_confidence>=0.9` 的别名
- 为兼容既有事实，投影层保留少量完整匹配的原文明示别名模板作为封闭白名单，不解析附加分句，不继续扩充自然语言表达变体
- `candidate`、`rejected`、低置信度、字段缺失、冲突、链式或不确定关系一律保持独立

角色阶段字段：

- `stage_hint`：阶段稳定名称
- `stage_type`：只允许 `age`、`form`、`identity`
- `stage_stability`：只允许 `stable`、`temporary`、`uncertain`
- `stable_difference`：布尔值，表示相对其他阶段存在稳定差异
- `evidence`：至少一条非空原文证据，每个阶段必须具备其他阶段不共享的独立证据
- `quality_warnings`：结构化质量警告数组，用于暴露证据不足、语境冲突和低置信度判断
- 自动拆分只接受 `stage_stability=stable`、`stable_difference=true`、类型合法且证据独立的阶段
- `temporary`、`uncertain`、字段缺失、类型冲突、证据不独立或少于两个合格阶段时统一回退默认阶段

Task 4 的 Dify Schema、Prompt 和输出归一化函数必须正式产出并校验以上字段，Task 2 只执行确定性准入、冲突隔离、去重和稳定排序

换装、伤病、情绪、遮挡、形态持续时间、别名是否明确和阶段是否稳定等自然语言语义判断属于 Dify 结构化契约职责，不在投影层通过追加正则解析

## 10. 构建与更新流程

角色库是 L2 之上的持久化、可重建投影层，不直接修改 L2 事实

构建流程采用无环的两阶段 Dify 调用：

1. 选择书籍、角色事实索引组和请求章节范围，锁定 L1 与角色 L2 的新鲜交集和覆盖水位
2. 通过稳定 keyset 分页完整读取角色事实，并按稳定 `entity` 建立不推断别名和阶段的临时候选
3. 对每个临时候选第一次调用 Task 4，只取得带证据的结构化别名和阶段语义信号
4. 将第一次调用结果适配为 Task 2 输入，由 Task 2 执行确定性强别名归并、冲突隔离和保守阶段拆分
5. 计算与上一版投影相比的受影响角色闭包，并为最终候选保守延续角色和阶段 ID
6. 对受影响的最终候选第二次调用 Task 4，生成合并后的核心档案和设计五官；第二次结果不得反向改写 Task 2 已确定的身份和阶段结构
7. 将成功、失败回退和未受影响复用结果写入构建暂存项，组装完整候选集合
8. 激活前复核覆盖和来源指纹，在单一事务中保存完整投影并切换当前 build
9. 页面读回并显示实际角色数、阶段数、覆盖范围、失败角色、待重试清单和质量警告

支持按部分章节构建，首次构建可以激活 `partial` 投影，失败候选不得伪造档案，必须进入质量摘要和待重试清单

已有角色库更新时，受影响且成功的角色使用新结果，受影响但失败且能唯一匹配上一版的角色沿用旧档案并标记失败或过期，未受影响角色直接复用；任何单角色失败都不得静默删除已有角色

增量闭包以完整事实快照的新增、删除和内容变化为种子，同时在旧、新两套 `confirmed` alias 关系图上扩展连通分量，纳入旧事实所有者、新候选所有者以及因归并或拆分相连的角色，迭代至集合稳定；无法唯一确定闭包时保守升级为全书候选重建

L2 完整读取使用固定过滤条件和 keyset 分页，排序键为 `chapter_index ASC, id ASC`，游标为上一页 `(chapter_index, id)`；返回少于页大小时结束，禁止使用 offset 或任意放大的单次 `limit` 替代完整读取

来源指纹由排序后的完整事实指纹、逐章覆盖状态与 `source_hash`、Task 2 规则版本、Task 4 Schema hash、Task 4 Prompt hash 和 Dify 工作流版本共同生成；构建结束激活前必须复核，任一材料变化则本次结果失效并重试

相同输入重复构建时角色 ID 和阶段 ID 必须保持稳定，L2 重跑产生的新事实 UUID 不得破坏角色库引用

## 11. 数据模型边界

第一阶段建议新增以下持久化实体：

- `character_library_builds`：构建范围、来源版本、状态和质量指标
- `character_library_build_items`：运行中角色候选、两阶段 Dify 结果、上一版回退、身份匹配审计、断点和重试状态
- `characters`：稳定角色主体、规范姓名、确认别名和汇总状态
- `character_stages`：角色阶段及核心档案
- `character_fact_links`：角色或阶段与来源事实指纹、章节和证据的链接

事实链接使用由书籍、索引组、章节、标准化事实和证据摘要生成的稳定指纹，不将会随 L2 重跑变化的 `l2_facts.id` 作为唯一长期引用

第一阶段每本书只保留一份当前可用角色库投影，`character_library_builds` 保留历次构建的范围、状态、质量和错误摘要，但不承诺从历史 build 读回当时的角色、阶段和事实快照

当前投影可来自全量或部分章节构建，索引组和实际章节范围记录在当前 build 中；同一本书同一时刻只有一个已激活的 `completed` 或 `partial` build

新投影的角色、阶段和事实链接写入，与 build 完成状态和当前版本激活必须在同一事务中提交；失败、取消或中断的 build 只记录自身状态，不删除或替换上一版可用投影

`character_library_builds` 增加独立于结果状态的 `control_state`，只允许 `active`、`pause_requested`、`paused`、`cancel_requested`，用于跨进程保存暂停和取消意图；结果状态继续使用 Task 3 已封板的 `running`、`completed`、`partial`、`failed`、`cancelled`

`character_library_build_items` 使用 `(build_id, item_key)` 主键和 `(build_id, candidate_fingerprint)` 唯一约束，外键 `build_id` 指向 `character_library_builds.id ON DELETE CASCADE`，状态只允许 `pending`、`running`、`succeeded`、`failed`、`reused`、`cancelled`

暂存项固定保存 `candidate_fingerprint`、`source_fact_fingerprints`、`input_payload`、`classification_output`、`profile_output`、`fallback_payload`、`previous_character_id`、`identity_match`、`quality_warnings`、`status`、`attempt_count`、`error_summary`、`started_at`、`heartbeat_at`、`completed_at`、`created_at` 和 `updated_at`

恢复时保留 `succeeded`、`reused` 和已记录回退的 `failed` 项，只将心跳超时的 `running` 项重置为 `pending`；暂停停止领取新项并允许进行中的调用落盘，取消将未开始项标记为 `cancelled` 且不得激活

最终激活前从暂存项组装“成功新结果 + 失败回退 + 未受影响复用”的完整集合，再调用 Task 3 原子替换；暂存项不得逐角色写入当前投影，也不构成可读历史角色快照

角色 ID 只在新候选与上一版角色形成唯一双向匹配时复用，候选边来自共享稳定事实指纹或 confirmed 名称集合交集，并按 `(共享事实数, confirmed 名称命中)` 词典序评分；只有新旧双方最高分都唯一、无并列且无冲突时复用，零匹配、一对多、多对一或并列时写 `identity_ambiguous`，并用 `book_id + 规范名 + confirmed aliases + 排序事实指纹` 的固定哈希生成新 ID

阶段 ID 只在所属角色已唯一延续后匹配，优先共享稳定事实指纹，其次完全相同的 `(stage_type, normalized stage_hint)`，同样要求双方唯一且无并列；默认阶段拆分、阶段归并或冲突时写质量警告，并用 `character_id + stage_type + normalized stage_hint + 排序事实指纹` 的固定哈希生成新 ID

Task 5 继续使用 analysis-summary Dify 工作流，API Key 唯一来源为 `DIFY_ANALYSIS_SUMMARY_WORKFLOW_API_KEY`，版本唯一来源为 `DIFY_ANALYSIS_SUMMARY_WORKFLOW_VERSION`，执行签名为 `dify:analysis_summary:<version>`

角色档案适配固定将 builder 的 `prompt` 映射为工作流 `prompt`，解析 `schema_json` 后映射为严格 JSON Schema，并将 `book_json`、`character_json`、`stages_json` 解析后组合为 `context_json={book, character, stages}`；其余输入固定为 `task_type=summary`、`schema_name=character_profile`、`strict_json_schema=true` 和显式模型参数

`character_fact_links` 通过 `stage_id` 归属阶段，再由阶段关联角色，不重复保存无法独立校验的 `character_id`

现有 `l2_subjects` 字段和编排绑定神奇生物主体，不作为角色库表复用

## 12. 页面与交互

### 12.1 入口与路由

- 书籍首页在章节线索、事实索引和提问管理之外新增角色库入口
- 路由为 `#/book/:id/characters`
- 面包屑为 `工作台 > 书籍 > 角色库`
- 角色形象索引继续留在事实索引页面

### 12.2 页面头部

- 标题：角色库
- 说明：聚合角色事实，形成可追溯的角色与阶段档案
- 主操作：更新角色库
- 次操作：前往事实索引
- 状态摘要：角色数、阶段数、覆盖章节、构建状态和最近更新时间
- 部分构建时明确提示后续更新可能新增角色或调整档案

### 12.3 B 方案主界面

默认使用全宽高密度角色表格，列包括：

- 角色姓名
- 确认别名
- 性别
- 阶段
- 年龄
- 身份或职业
- 外形事实数
- 档案状态
- 最近更新

工具栏提供姓名或确认别名搜索、全部或多阶段或信息不足筛选和排序

点击角色行打开右侧详情抽屉，关闭抽屉后恢复完整表格宽度

### 12.4 详情抽屉

详情抽屉桌面宽度约 560 至 640px，内容可独立纵向滚动，页面左侧仍保留部分表格作为上下文

抽屉内容包括：

- 角色姓名、确认别名、性别和档案状态
- 阶段切换
- 年龄
- 身份或职业
- 稳定外形
- 稳定气质
- 原文五官
- 带“设计推导”标记和说明的设计五官
- 外形事实与证据列表

事实证据按类型和章节展示事实摘要及原文摘录，支持展开查看，不展示无关剧情事实或原始 JSON

### 12.5 页面状态

页面必须覆盖：

- 加载中和 API 错误
- 无章节
- L1 未建立
- 无角色事实索引组
- 角色事实尚未完成任何章节
- 事实部分可用但存在失败章、空章或过期章
- 事实已具备但角色库尚未建立
- 角色库构建中
- 角色库部分可用
- 角色库全量可用
- 角色库需更新
- 搜索无结果
- 深链接角色已不存在

## 13. 错误处理与任务语义

角色库构建属于可追踪长任务，必须复用全局任务管理能力，支持进度、暂停、恢复、取消和失败重试，不把任务状态只放在页面组件中

部分失败时保存已完成角色和断点，只重跑失败或受影响角色，不默认清空已有可用角色库

Dify 不可用时不得伪造完整角色档案，页面保留上一版可用结果并显示本次更新失败

## 14. 验收与测试

### 14.1 数据与服务测试

- 严格按书籍和角色索引组隔离来源事实
- 无稳定名称主体不会进入正式角色列表
- 强证据别名可稳定归并，弱证据不会误合并
- 相同输入重复构建保持角色 ID 和阶段 ID 稳定
- L2 重跑后事实链接可通过稳定指纹重建
- 临时外形不会进入稳定外形
- 阶段只在三个准入条件同时满足时拆分
- 原文五官与设计五官分别保存和返回
- 部分章节构建、增量更新、失败续跑和过期判断正确

### 14.2 前端测试

- 书籍首页角色库入口、路由和面包屑正确
- 表格搜索、筛选、排序和角色选中正确
- 详情抽屉打开、切换角色、切换阶段和关闭正确
- 所有前置状态和空态具有明确下一步入口
- 桌面和移动端没有文字或控件重叠
- 抽屉打开时表格上下文仍可识别

### 14.3 样板书验证

- 使用《哥，别舔女主了！妹宝被你死对头亲晕了》验证 190 章的小规模端到端构建
- 使用《凰宫梦》179 人正式基线回归角色召回和别名归并
- 使用《离婚后她惊艳了世界》验证基础角色与阶段记录分离

## 15. 后续演进

后续阶段可以在不改变角色和阶段稳定 ID 的前提下增加：

- 人工角色归并、拆分和别名裁决
- 阶段差异对比和人工调整
- 角色图片生成、质检、版本和附件映射
- 关系图谱和关键事件时间线
- 将角色事实提取入口逐步并入角色库流水线

这些能力不属于第一阶段验收范围
