## 2. 目标与范围

角色库用于把分散在章节中的角色事实聚合为稳定、可浏览、可追溯的角色与阶段档案

第一阶段采用展示优先策略，提供角色表格、角色详情抽屉、阶段切换、核心档案和外形事实证据，不提供人工归并工作台

本期包含：

- 书籍首页新增独立角色库入口
- 支持按部分章节建立和增量更新角色库
- 只收录有稳定名称的角色
- 从 L2 角色事实聚合角色和阶段
- 展示姓名、确认别名、性别、阶段、年龄、身份或职业、稳定外形、稳定气质、原文五官、设计五官
- 展示与角色外形形象有关的事实及章节证据
- 展示构建覆盖、数据新鲜度和质量警告

本期不包含：

- 角色图片生成、重绘、上传和图片入口
- 完整角色关系图谱
- 人工合并、拆分和别名裁决工作台
- 将现有角色形象索引从事实索引迁出
- 跨书角色库
- 任意字段模板设计器

## 3. 术语与依赖链

L1 是章节线索和角色路标，不是事实索引；角色事实来自 L2 角色专项索引

角色库的正确依赖链为：

`章节原文 → L1 角色路标 → L2 角色事实 → 角色归并与阶段拆分 → 角色核心档案`

现有 `characters` 或其他实际承载角色事实的 L2 索引组继续由事实索引功能管理，角色库只读取其已完成且新鲜的事实，不修改 L2 原始事实

## 4. 角色入库规则

正式角色列表只收录有稳定名称的主体，包括：

- 原文明示的本名
- 原文明示的化名或改名
- 能稳定唯一指向一个主体的专属称号或稳定绰号

以下对象不得进入正式角色列表：

- 组织、势力、物品、地点、境界和能力名称
- 无法唯一指向具体主体的泛称
- 临时描述性称谓，如黑衣人、侍卫、路人和某人的母亲
- 只有模型推断、没有原文命名依据的主体

同名、疑似别名或疑似同人但缺少强证据时保持为独立候选，不自动合并

## 5. 核心档案

角色层保存：

- 稳定角色 ID
- 书籍 ID
- 规范姓名
- 确认别名
- 性别
- 首次和最近出现章节
- 关联阶段数
- 关联外形事实数
- 档案状态和更新时间

阶段层保存：

- 稳定阶段 ID
- 所属角色 ID
- 阶段名称
- 阶段类型，如年龄时期或形态
- 起止章节或适用章节范围
- 年龄
- 身份或职业
- 稳定外形
- 稳定气质
- 原文五官
- 设计五官
- 来源事实与证据引用
- 构建状态、质量状态和更新时间

所有字段都允许未知，不为了填满档案而猜测

## 6. 阶段识别

阶段采用保守自动拆分，默认每个角色只有一个默认阶段

只有以下条件同时成立时才创建独立阶段：

- 原文存在明确的年龄时期、时间节点、身份形态或物种形态变化
- 不同阶段存在稳定外形、体型、年龄感、气质或形态差异
- 每个阶段都有独立可追溯的事实和原文证据

可接受的阶段示例包括幼年、少年、成年、老年、人类形态、非人形态、鬼魂形态和投胎后形态

临时伤病、哭泣、战损、换装、易容、一次性戴面罩或面纱、短暂力量异变和单场景情绪不得作为阶段拆分依据

长期稳定佩戴的面罩、面纱或其他遮挡物可以进入对应阶段的稳定外形，但必须有跨章节或明确长期设定证据

## 7. 事实层与设计层

角色档案必须明确分开原文事实和设计推导

原文事实层包括：

- 原文明示的姓名、别名、性别、年龄、身份和职业
- 原文明示的稳定体型、肤色、发型、服饰惯例、标志物和其他稳定外形
- 原文明示或由多处稳定行为支持的气质
- 原文明示的脸型、眉形、眼型、鼻形、唇形、下颌、骨相和其他五官特征

设计层只用于补足角色形象设计所需但原文缺失的五官组合：

- 结合年龄、性别、稳定外形和稳定气质生成差异化五官设计
- 不得改变或覆盖原文明示特征
- 不得把题材套路、模型偏好或审美模板写成角色事实
- 必须显示“设计推导”标记
- 必须显示“基于年龄、稳定外形与气质生成，不等同于原文事实”说明
- 必须记录使用的事实依据和生成版本

## 8. 稳定外形与稳定气质

稳定外形只保留跨场景成立或被原文明示为长期设定的特征

受伤、哭泣、醉酒、脸红、疲惫、病后憔悴、单次服装、临时战损和短暂遮挡不进入稳定外形

稳定气质用于辅助后续角色形象生成，应来自角色长期个性表达、稳定行为方式、叙述性评价或多处相互支持的原文证据

单次情绪、单一角色的偏见、传闻、表演性人格和伪造文本不得直接成为稳定气质；存在表里人格时必须保留语境层级

## 9. 角色事实质量要求

### 9.1 结构准确度

- 角色事实的 `category` 必须为 `character`
- `fact_type` 只允许 `identity`、`alias`、`appearance`、`age`、`personality`、`background`
- entity、fact 和 evidence 不得为空
- importance 和 confidence 必须在 0 至 1 范围
- 同章完全重复事实必须在聚合前去重

### 9.2 主体准确度

- entity 必须是稳定主称或明确标记的候选主体
- 昵称、头衔和关系称谓不得无条件成为独立角色
- 自动别名合并只允许原文明示改名、化名揭示或姓名与唯一专属称号互证等强证据
- 同章出现、共享关系人、模糊字符串相似和模型自行列出的 aliases 不足以自动合并

### 9.3 事实准确度

- 每条进入档案的事实至少有一条直接证据和章节定位
- 推断内容必须标明推断性质，不能混入原文事实
- 稳定外形不得混入临时状态
- 公开身份、真实身份、回忆、传闻、角色误判和伪造文本必须保留来源语境
- 冲突事实不得静默覆盖，应在质量状态中暴露

### 9.4 完整度

- 使用 L1 角色路标作为候选召回和异常空章对照，不把 L1 当作档案事实来源
- L1 有明确角色信号但 L2 无角色事实的章节标记为疑似异常空章
- 明确区分原文无信息、未覆盖章节和疑似漏抽
- 构建结果必须显示 L1、L2 和角色库各自的章节覆盖范围
- 章节哈希、Prompt、Schema 或工作流版本变化后，受影响角色库标记为需更新

### 9.5 验收目标

- 机器结构校验通过率 100%
- 抽样角色事实准确率不低于 95%
- 抽样有稳定名称角色召回率不低于 95%
- 高价值身份和别名误合并为 0
- 阶段拆分必须全部具备独立证据
- 设计五官与原文事实混写为 0

### 9.6 结构化投影输入契约

角色库投影层只消费已经完成语义判断的结构化字段，不负责从自然语言事实正文推导别名关系、阶段稳定性或持续时间

角色别名字段：

- `alias_relation`：只允许 `confirmed`、`candidate`、`rejected`
- `alias_confidence`：0 至 1 的数值
- `evidence`：至少一条非空原文证据
- 自动归并只接受 `alias_relation=confirmed` 且 `alias_confidence>=0.9` 的别名
- 为兼容既有事实，投影层保留少量完整匹配的原文明示别名模板作为封闭白名单，不解析附加分句，不继续扩充自然语言表达变体
- `candidate`、`rejected`、低置信度、字段缺失、冲突、链式或不确定关系一律保持独立

角色阶段字段：

- `stage_hint`：阶段稳定名称
- `stage_type`：只允许 `age`、`form`、`identity`
- `stage_stability`：只允许 `stable`、`temporary`、`uncertain`
- `stable_difference`：布尔值，表示相对其他阶段存在稳定差异
- `evidence`：至少一条非空原文证据，每个阶段必须具备其他阶段不共享的独立证据
- `quality_warnings`：结构化质量警告数组，用于暴露证据不足、语境冲突和低置信度判断
- 自动拆分只接受 `stage_stability=stable`、`stable_difference=true`、类型合法且证据独立的阶段
- `temporary`、`uncertain`、字段缺失、类型冲突、证据不独立或少于两个合格阶段时统一回退默认阶段

Task 4 的 Dify Schema、Prompt 和输出归一化函数必须正式产出并校验以上字段，Task 2 只执行确定性准入、冲突隔离、去重和稳定排序

换装、伤病、情绪、遮挡、形态持续时间、别名是否明确和阶段是否稳定等自然语言语义判断属于 Dify 结构化契约职责，不在投影层通过追加正则解析

## 10. 构建与更新流程

角色库是 L2 之上的持久化、可重建投影层，不直接修改 L2 事实

构建流程分为：

1. 选择书籍、角色事实索引组和当前可用章节范围
2. 计算 L1 与角色 L2 的新鲜交集范围
3. 过滤无稳定名称主体和非角色对象
4. 使用强证据归并规范姓名和确认别名
5. 为角色和阶段生成稳定 ID，并为来源事实生成稳定指纹
6. 保守识别角色阶段
7. 调用 Dify 通用分析工作流生成结构化核心档案和设计五官
8. 保存构建批次、角色、阶段、事实链接、质量指标和版本信息
9. 页面读回并显示实际角色数、阶段数、覆盖范围和质量警告

支持按部分章节构建，后续章节进入或上游事实变化时只重建受影响角色

相同输入重复构建时角色 ID 和阶段 ID 必须保持稳定，L2 重跑产生的新事实 UUID 不得破坏角色库引用

## 11. 数据模型边界

第一阶段建议新增以下持久化实体：

- `character_library_builds`：构建范围、来源版本、状态和质量指标
- `characters`：稳定角色主体、规范姓名、确认别名和汇总状态
- `character_stages`：角色阶段及核心档案
- `character_fact_links`：角色或阶段与来源事实指纹、章节和证据的链接

事实链接使用由书籍、索引组、章节、标准化事实和证据摘要生成的稳定指纹，不将会随 L2 重跑变化的 `l2_facts.id` 作为唯一长期引用

第一阶段每本书只保留一份当前可用角色库投影，`character_library_builds` 保留历次构建的范围、状态、质量和错误摘要，但不承诺从历史 build 读回当时的角色、阶段和事实快照

当前投影可来自全量或部分章节构建，索引组和实际章节范围记录在当前 build 中；同一本书同一时刻只有一个已激活的 `completed` 或 `partial` build

新投影的角色、阶段和事实链接写入，与 build 完成状态和当前版本激活必须在同一事务中提交；失败、取消或中断的 build 只记录自身状态，不删除或替换上一版可用投影

`character_fact_links` 通过 `stage_id` 归属阶段，再由阶段关联角色，不重复保存无法独立校验的 `character_id`

现有 `l2_subjects` 字段和编排绑定神奇生物主体，不作为角色库表复用

## 12. 页面与交互

### 12.1 入口与路由

- 书籍首页在章节线索、事实索引和提问管理之外新增角色库入口
- 路由为 `#/book/:id/characters`
- 面包屑为 `工作台 > 书籍 > 角色库`
- 角色形象索引继续留在事实索引页面

### 12.2 页面头部

- 标题：角色库
- 说明：聚合角色事实，形成可追溯的角色与阶段档案
- 主操作：更新角色库
- 次操作：前往事实索引
- 状态摘要：角色数、阶段数、覆盖章节、构建状态和最近更新时间
- 部分构建时明确提示后续更新可能新增角色或调整档案

### 12.3 B 方案主界面

默认使用全宽高密度角色表格，列包括：

- 角色姓名
- 确认别名
- 性别
- 阶段
- 年龄
- 身份或职业
- 外形事实数
- 档案状态
- 最近更新

工具栏提供姓名或确认别名搜索、全部或多阶段或信息不足筛选和排序

点击角色行打开右侧详情抽屉，关闭抽屉后恢复完整表格宽度

### 12.4 详情抽屉

详情抽屉桌面宽度约 560 至 640px，内容可独立纵向滚动，页面左侧仍保留部分表格作为上下文

抽屉内容包括：

- 角色姓名、确认别名、性别和档案状态
- 阶段切换
- 年龄
- 身份或职业
- 稳定外形
- 稳定气质
- 原文五官
- 带“设计推导”标记和说明的设计五官
- 外形事实与证据列表

事实证据按类型和章节展示事实摘要及原文摘录，支持展开查看，不展示无关剧情事实或原始 JSON

### 12.5 页面状态

页面必须覆盖：

- 加载中和 API 错误
- 无章节
- L1 未建立
- 无角色事实索引组
- 角色事实尚未完成任何章节
- 事实部分可用但存在失败章、空章或过期章
- 事实已具备但角色库尚未建立
- 角色库构建中
- 角色库部分可用
- 角色库全量可用
- 角色库需更新
- 搜索无结果
- 深链接角色已不存在

## 13. 错误处理与任务语义

角色库构建属于可追踪长任务，必须复用全局任务管理能力，支持进度、暂停、恢复、取消和失败重试，不把任务状态只放在页面组件中

部分失败时保存已完成角色和断点，只重跑失败或受影响角色，不默认清空已有可用角色库

Dify 不可用时不得伪造完整角色档案，页面保留上一版可用结果并显示本次更新失败

## 14. 验收与测试

### 14.1 数据与服务测试

- 严格按书籍和角色索引组隔离来源事实
- 无稳定名称主体不会进入正式角色列表
- 强证据别名可稳定归并，弱证据不会误合并
- 相同输入重复构建保持角色 ID 和阶段 ID 稳定
- L2 重跑后事实链接可通过稳定指纹重建
- 临时外形不会进入稳定外形
- 阶段只在三个准入条件同时满足时拆分
- 原文五官与设计五官分别保存和返回
- 部分章节构建、增量更新、失败续跑和过期判断正确

### 14.2 前端测试

- 书籍首页角色库入口、路由和面包屑正确
- 表格搜索、筛选、排序和角色选中正确
- 详情抽屉打开、切换角色、切换阶段和关闭正确
- 所有前置状态和空态具有明确下一步入口
- 桌面和移动端没有文字或控件重叠
- 抽屉打开时表格上下文仍可识别

### 14.3 样板书验证

- 使用《哥，别舔女主了！妹宝被你死对头亲晕了》验证 190 章的小规模端到端构建
- 使用《凰宫梦》179 人正式基线回归角色召回和别名归并
- 使用《离婚后她惊艳了世界》验证基础角色与阶段记录分离

## 15. 后续演进

后续阶段可以在不改变角色和阶段稳定 ID 的前提下增加：

- 人工角色归并、拆分和别名裁决
- 阶段差异对比和人工调整
- 角色图片生成、质检、版本和附件映射
- 关系图谱和关键事件时间线
- 将角色事实提取入口逐步并入角色库流水线

这些能力不属于第一阶段验收范围
