# Agent 派发与交接模板

## 1. 派发模板

```md
任务：
<单一、明确的任务名称>

执行方式：
<subagent | 新线程>

当前关卡：
<范围 | 契约 | 设计 | 实现 | 审查 | 验收>

目标：
<完成后必须成立的结果>

信源：
- <必须读取的文件或提交>

允许：
- <可修改文件或可执行动作>

禁止：
- <不得修改的文件或不得进入的后续 Task>

文件所有权：
- <当前执行方独占的文件或目录>

必须检查：
- <关键不变量和验收条件>

停止条件：
- BLOCKER: <出现后立即停止>
- QUESTION: <需要总控或用户裁决>
- SCOPE_ALERT: <规模或职责超出控制卡>
- COLLISION_ALERT: <其他执行方正在修改共享文件>
- IRREVERSIBLE_ALERT: <发现尚未审查的不可逆风险>

提交权限：
<默认不允许 | 允许提交 | 允许推送与 PR>

输出：
按本文档交接模板返回，不复制全量命令输出或完整推理过程
```

## 2. 交接模板

```md
状态：PASS | BLOCKED | NEEDS_DECISION

实际完成：
- <最多 5 项>

修改文件：
- <精确路径；只读任务写“无”>

验证：
- <命令或读回动作：结果>

BLOCKER：
- <仅列当前阻断项；无则写“无”>

QUESTION：
- <仅列需要裁决的问题；无则写“无”>

FOLLOW_UP：
- <不阻断当前 Task 的建议；无则写“无”>

剩余风险：
- <已知但可接受的风险；无则写“无”>
```

## 3. 上下文控制

- 总控只保留控制卡、裁决、提交、验收证据和下一步授权
- 执行方不回传全量命令输出、完整 diff、每轮修复过程或已解决问题的长篇分析
- 需要跨线程保留的决策、状态和验收证据必须回写项目文件
- 新线程的原始探索留在该线程，总控只记录线程入口、状态、有效决策、提交或产物和验收结果

删除影响：执行方虽然分离，但过程内容仍被全量回灌到总控上下文，无法达到隔离效果
