# Task 控制卡

非简单 Task 开始前，总控使用本模板锁定执行边界，并在关键决策、阻断项或授权变化时同步更新

```md
## Task <编号与名称>

当前关卡：范围 | 契约 | 设计 | 实现 | 验收

目标：
<本 Task 完成后必须成立的结果>

本期包含：
- <职责或交付物>

明确不包含：
- <不得顺手实现的能力>

输入契约：
- <上游对象、字段、状态和质量要求>

输出契约：
- <下游可依赖的对象、字段、失败和降级语义>

已确认决策：
- DECISION: <已回写项目信源的决策>

未决问题：
- QUESTION: <未裁决前不得隐式实现的问题>

停止条件：
- BLOCKER: <触发后必须暂停的条件>

后续清单：
- FOLLOW_UP: <不阻断当前 Task 的增强>

审查关：
- <是否需要契约、不可逆设计、规格或质量审查>

完成证据：
- <测试、读回、数量、截图、文档或远端状态>

当前授权：
<仅审查 | 允许实现 | 允许提交 | 允许推送与 PR>
```

控制卡应保持简短，引用已有设计基线和实施计划，不复制长篇规格

删除影响：授权边界、停止条件和完成证据只存在于临时对话，总控和执行线程容易对当前任务产生不同理解
