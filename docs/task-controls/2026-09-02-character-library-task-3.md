# Task 3 控制卡：角色库持久化投影

- 日期：2026-09-02
- 当前关卡：已完成
- 设计基线：[`docs/character-library-design.md`](../character-library-design.md)
- 实施计划：[`docs/superpowers/plans/2026-09-02-character-library.md`](../superpowers/plans/2026-09-02-character-library.md)

## 目标

建立角色库的持久化边界，使每本书有一份可原子替换、可重建、可追溯来源的当前投影，并保留历次构建记录

## 本期包含

- 新增构建、角色、阶段和事实链接四类持久化实体
- 实现构建记录创建与状态更新
- 实现当前投影的事务写入、激活和回滚
- 实现当前角色库状态、列表和详情查询
- 保证角色 ID、阶段 ID 和事实指纹的持久化语义不依赖 L2 事实 UUID

## 明确不包含

- Dify Schema、Prompt、归一化或真实角色档案生成
- L1、L2 覆盖计算和角色库构建任务编排
- 前端 API、页面、表格和详情抽屉
- 历史角色详情快照、版本对比和人工回滚
- 人工归并、拆分、别名裁决和稳定 ID 生成算法

## 输入契约

- 上游提供书籍 ID、角色索引组、章节范围和非空来源指纹
- 上游提供不透明但稳定的角色 ID 和阶段 ID，持久化层不根据姓名自行生成 ID
- 同名不同人必须使用不同角色 ID，姓名不具备唯一性
- 每个阶段必须引用同一输入集合中存在的角色，每个事实链接必须引用同一输入集合中存在的阶段
- JSON 字段接受结构化数组或对象，不接收已序列化的 SQLite 字符串

## 输出契约

- 每本书最多有一个 `is_current=1` 的 `completed` 或 `partial` build
- 列表和详情只返回当前 build 关联的投影，不返回历史快照
- 返回值中的 JSON 字段已解析，不向上层暴露存储字符串
- 激活新投影时，投影写入、旧版取消激活、新 build 最终状态、覆盖和质量摘要在同一事务中提交
- 事务失败、build 失败、取消或中断时，上一版当前投影保持完整可读

## 已确认决策

- DECISION: 第一阶段保留构建记录历史，不保留历史角色详情快照
- DECISION: 角色 ID 和阶段 ID 是逻辑对象身份，build ID 是一次构建尝试身份，两者不得混用
- DECISION: 每本书只维护一份当前可用投影，可以是部分章节结果
- DECISION: 每本书同一时刻只允许一个未终结的角色库 build，新建重复 build 必须被拒绝或显式复用现有 build
- DECISION: 当前投影切换必须使用单一 SQLite 事务，不允许先删旧投影再单独更新 build 状态
- DECISION: `character_fact_links` 不重复保存 `character_id`，通过 `stage_id` 反查角色归属
- DECISION: 持久化层在写入前校验书籍归属、重复 ID、阶段引用和事实链接引用，不依赖外键错误作为正常校验流程

## 不可逆设计审查

### 不变量

- `is_current` 只能为 0 或 1，且只有 `completed` 或 `partial` build 可以成为当前版本
- 任何当前角色、阶段和事实链接都属于同一本书和同一当前 build
- 角色姓名可重复，角色 ID 不可重复；阶段 ID 不可重复且只属于一个角色
- 事实链接的稳定身份是 `stage_id + fingerprint`，L2 事实 UUID 变化不影响身份
- 失败路径不能破坏已激活投影

### 历史、重试与并发

- build 表保留每次尝试的输入范围、来源指纹、终结状态、覆盖、质量和错误摘要
- 相同来源指纹重试可以创建新 build 记录，但不改变角色和阶段稳定 ID
- 未终结 build 存在时禁止同书并发新建，避免较旧输入在较晚完成后反向覆盖新结果
- 系统异常退出后遗留的未终结 build 必须由 Task 5 的恢复或取消语义处理，Task 3 只提供可校验的状态更新能力

### 删除、迁移与回滚

- 删除书籍时四类角色库数据随书籍级联删除，不增加脱离书籍的独立保留语义
- Task 3 只新增表和索引，不迁移或改写现有 L1、L2、分析和书籍数据
- 代码回滚时已创建的空表可保留，不得在无备份时自动删表
- 投影已有数据后如需修改主键或快照语义，必须另立迁移计划和可恢复备份，不在普通启动 SQL 中破坏性重建

### 备选方案

- 本期选择：构建记录历史加单份当前投影，满足展示、失败保留和重建需求，复杂度最低
- 未选择：以 `(build_id, stable_id)` 作为复合主键保留所有快照，因本期无历史版本浏览、对比和回滚需求而延期
- 未选择：把阶段和事实嵌入角色 JSON，因会破坏阶段稳定 ID、证据追溯和后续增量更新而不采用
