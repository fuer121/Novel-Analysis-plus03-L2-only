# Superpowers 工作区

## 1. 目录职责

- `plans/`：保存可执行实施计划，包括活跃、已完成和已被替代的计划
- `specs/`：保存设计过程、审查 Brief 和执行记录
- `evaluations/`：保存专项评估方法、脚本和结果说明

删除影响：执行者无法区分当前计划、历史证据和支持材料

## 2. 生效状态

- 目录位置、文件名和创建日期只用于定位材料，不单独决定文档是否当前生效
- 实施计划是否活跃，由对应设计基线、计划自身状态和总控台账共同确认
- 设计基线定义产品边界、数据语义和验收标准，实施计划定义执行顺序、任务拆分和验证方式
- 计划与当前设计基线冲突时，先暂停执行并由总控裁决，不得以计划文件隐式改写设计基线
- 已完成或已被替代的计划继续保留作历史证据，不作为新任务的当前规格

删除影响：新线程可能忽略活跃计划，或者让过期计划覆盖当前设计基线

## 3. 读取顺序

1. 从 `Agent.md` 确认功能的设计基线、协作规则和计划入口
2. 读取相关设计基线，确认当前范围和状态
3. 读取设计基线指向的活跃实施计划
4. 结合总控台账或目标功能文档确认当前任务和下一步
5. 只在需要追溯决策或验证证据时读取历史计划、`specs/` 或 `evaluations/`

删除影响：路径地图和规格优先级混在一起，执行者会把“去哪里找”误解为“当前以谁为准”
